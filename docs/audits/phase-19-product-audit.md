## Notes on severity classification

D-19-1 is P1 rather than P2 because it is simultaneously (a) a CI-blocking regression on `main` and (b) a genuine WCAG accessible-name-uniqueness problem in a shipped, authenticated surface — not merely cosmetic. D-19-2 is P2, not P1: no data is lost, no core workflow breaks, and the underlying documents really are gone (correct outcome), but the operational-noise/false-alarm risk is real enough not to be P3. D-19-3 is P1: a full, multi-hour production worker outage is exactly the plan's P1 definition ("processing failure ... inaccessible primary workflow"), even though the code fix itself predates this register entry — the entry exists to close the documentation gap and record the incident where the plan requires it to live. D-19-4 is P1: it broke CI on `main` (same bar as D-19-1) — recorded honestly as a defect this same session introduced and caught, not omitted because it was self-inflicted.
