# Palimnote × ScholarLens Integration Program (Phases 25–31)

## Context

The owner has acquired a full license to ScholarLens (MIT-licensed; created by a collaborator who is now co-developing Palimnote's upgrade) and approved the hybrid product vision in `/Users/hyderhusainarastu/Project/Palimnote_Research/palimnote-scholarlens-hybrid-brief.md`: a unified scholarly environment connecting **passage → claim → evidence → disagreement → field map → research gap → reading plan → grounded writing**. Palimnote reads *vertically* into a text (critical editions, prerequisites, roadmaps); ScholarLens reads *horizontally* across a field (claim extraction, contradiction detection, debate clustering, hypothesis generation). The merger produces three workspaces — **Palimnote Read** (exists), **Palimnote Research** (new), **Palimnote Write** (exists, extended) — over one library, one evidence store, one knowledge graph, one project model.

This plan defines how to build it without compromising Palimnote's existing goals: the cost ceiling ($1 soft / $5 hard per run), the anti-hallucination posture (facts only from real lookups; every claim anchored to an exact passage), the eval-gated model-promotion discipline, and the stability of the shipped edition pipeline.

## Dual-track evidence model (empirical preserved + humanities added)

The claim's **type decides which analytical track applies** — never one scorer pretending to cover both.

**Track 1 — Empirical (preserved verbatim from ScholarLens):**
- `evidence_strength.py` ported as-is: study-design tiers (meta-analysis > RCT > cohort > controlled > observational > case study), quantitative-signal weights (p-value, effect size, CI, sample size, percentage, dispersion, significance), hedging cap. Pure, deterministic, unit-tested, auditable signals.
- The 4-way judge (contradiction/nuance/support/unrelated + methodological/findings/theoretical/scope) stays the validated core for empirical claim pairs, certified by the ported 42-pair gold set (macro-F1 0.788 baseline to match or beat).

**Track 2 — Humanities/interpretive (new, same architectural DNA):**
- A **textual-support scorer**, built exactly like the empirical one (pure, deterministic, named signals, no LLM) but with humanities signals: direct primary-text quotation present; locus citations (Bekker/Stephanus/page references — reusing `packages/ingestion`'s existing `classicalReferences.ts` recognizers); breadth of textual support (multiple independent loci vs one); engagement with rival readings ("contra", "pace", named opposing scholars); original-language evidence (reusing the existing foreign-script detection); apparatus density (footnoted support). Same hedging cap. Output labeled **"textual support"**, never "evidence strength" — the two scores are visibly different dimensions, not one scale.
- Claims that fit neither track are honestly **unscored** (no fake number), matching the peer-reviewed-null-means-unknown precedent.
- **Judge extensions for interpretive disagreement**: the relationship vocabulary gains the brief's humanities-critical distinctions in an eval-gated stage — foremost `different_definition`, `interprets_differently`, and `different_scope/conditions` — because in interpretive disciplines an apparent contradiction often dissolves into a definitional or interpretive difference, and mislabeling that as contradiction is the product's number-one scholarly risk (brief: "False contradictions"). The judge prompt gains a discipline-aware branch: before classifying, determine whether the claims share definitions and address the same passage/explanatory level.
- **A humanities gold set is a prerequisite for promotion**: ~30–40 hand-labeled claim pairs drawn from the Aristotle-vice corpus (the owner's own research domain; the Roochnik/Brickhouse/NE secondary literature already in the library and `baseline-test/` fixtures), labeled with the extended vocabulary, train/test split, before any humanities judge prompt ships. Until it passes its floors, humanities pairs run through the base 4-way judge with `interpretive` flagged as a category, never silently misclassified.
- **Claim taxonomy** (staged): stage 1 ships ScholarLens's validated shape (claim + confidence + section) plus a `claim_nature` axis — `empirical | textual | interpretive | historical | conceptual | normative | definitional | methodological` — extracted at claim time (it routes scoring + judge branch); stage 2 extends toward the brief's full 14-type argumentative taxonomy (premise/conclusion/objection/reply/qualification/speculative) once the reader-side passage-role suggestions (brief §Palimnote Read) land. Every taxonomy value is a DB enum with CHECK constraints — no free-text taxonomy columns (a ScholarLens weakness the port fixes).
- The **Evidence Chamber is discipline-neutral by design** (its "point of divergence" already includes definitional/scope/method differences) — it renders whichever track's scores exist and states which dimension is being shown.

## What ScholarLens contributes (exploration findings, 2026-07-25)

**Crown jewels — port faithfully, treat as licensed IP:**
- The **contradiction-judge prompt** (`agents/contradiction_agent.py::judge_pair`): decision-tree structure, proxy-vs-orthogonal measurement distinction, 6 few-shots targeting the nuance/contradiction boundary. Measured macro-F1 **0.788** / Cohen's kappa **0.683** over 4 documented iterations.
- The **claim-extraction prompt** (HARD RULES + BAD/GOOD few-shot pairs; extracts 6–10 falsifiable, evidence-grounded claims directly from source text, never from summaries).
- **`utils/evidence_strength.py`** — deterministic, pure, regex-based evidence scoring (study-design tiers + quantitative-signal weights + hedging cap → 0–1 score + named signals + `evidence_gap`). Zero LLM calls; ports to a pure Vitest-tested TS module.
- The **two-stage pipeline shape**: hybrid BM25 + dense cosine pre-filter (union, tagged `dense`/`bm25`/`both`) cuts O(n²) pairwise LLM judgments to a small fraction — exactly Palimnote's cost discipline.
- The **label-then-validate anti-hallucination pattern**: LLM cites `[CONFLICT_N]` labels, post-parse validation drops fabricated references — reusable anywhere an LLM must cite DB-verifiable IDs.
- **Computed novelty scoring**: hypothesis novelty = cosine distance to nearest library chunk (never LLM self-assessment).
- **Gold sets + eval harness**: `eval/gold_claims.json` (42 labeled pairs, 3 domains, train/test split), `eval/gold_search.json`, macro-F1/kappa/binary-tension metrics, honest "no meaningful difference" verdicts.
- Corpus import (Semantic Scholar/OpenAlex/arXiv w/ dedup) and monitoring design (topic cadence, citation alerts, author-follow, off-process cron).

**Weaknesses fixed by the port (do not copy):** manual JSON fence-stripping instead of structured output; no LLM retry logic; free-text taxonomy columns with no DB constraints; in-memory job store; 32k-char truncation of long documents; incompatible same-named relevance-tier scales.

**What Palimnote already has that the port extends rather than rebuilds:** `work_claim` (passage-grounded claims), `generated_claim`/`claim_evidence`/`evidence_span` (stance-labeled evidence), `work_relationship_candidate`/`work_relationship_judgment` (paid cross-work claim judgments with basis-hash provenance), `edge_type` values `disagrees_with`/`criticizes`/`responds_to`, `concept_kind` `"debate"`, the `{quote,prefix,suffix}` anchor idiom + `findQuoteOffset`, the budget/usage-log machinery, structured-output client with retries, and the per-phase feature-flag pattern.

## Improvements to the ScholarLens features (grounded in this project and the owner's research)

The port is not a copy — each feature is upgraded where Palimnote's existing capabilities or the research project's findings (`/Users/hyderhusainarastu/Project/Palimnote_Research`, esp. `research/palimnote_upgrade_recommendations.md`) make it strictly better:

1. **Citation-graph-aware disagreement judgment** *(new capability ScholarLens lacks)*: Palimnote knows when claim A's work actually **cites** claim B's work (resolved `citation` rows + canonical `work_identity`). The judge receives this as context and the relationship row stores it (`engagement: direct_citation | none_detected`) — distinguishing *direct engagement* (reply, critique, polemic — explicit in humanities scholarship) from *independent convergence/disagreement*. Deterministic pre-join, zero AI cost.
2. **Locus-based candidate retrieval** *(humanities-specific third Stage-1 channel)*: two claims anchored to or citing the same classical locus (Bekker/Stephanus, via the existing `classicalReferences.ts` recognizers) or the same canonical work+section become candidate pairs regardless of vocabulary distance — deterministic, free, tagged `retrieval_source: "locus"` beside `dense`/`bm25`.
3. **Structural extraction beats regex sectioning**: claim extraction runs map-reduce over GROBID `text_block` structure (fixing ScholarLens's 32k-char truncation), and claims are *structurally* never drawn from bibliography/footnote/caption blocks — apparatus exclusion by block kind, not regex guessing. Every claim gets a real re-locatable anchor (`text_block` FK + quote fingerprint), not just a loose source quote.
4. **Two-level credibility**: source-level multi-dimensional credibility (existing system: publication rigor, creator expertise, host provenance…) × claim-level evidence-strength/textual-support — the Evidence Chamber shows both dimensions, never collapsed into one number (research pillar: multidimensional trust, popularity never scored as credibility).
5. **Trust calibration + verifiable offloading** *(the research paper's central pillar, applied)*: every claim/relationship/hypothesis card carries confidence + provenance + a one-click jump to the exact anchored passage; all generated objects are review-first (`verification_status` transitions reused from the annotation pattern). **Explicitly no auto-endorsement pathway** — the upgrade doc (Tier 3.2) records this as a research-gated product decision that must not be built quietly; the plan honors that.
6. **Canonical-identity dedup for corpus import**: ScholarLens dedupes imports by title-key; Palimnote's canonical `work_identity` + bibliographic resolution (Crossref/OpenAlex/etc.) makes corpus import edition-aware and merge-reversible.
7. **Debate-aware reading routes**: gaps/debates feed the existing `@ice/roadmap` ranking + reader-level + curriculum-stage machinery (the research project's sequencing/cognitive-load co-pillar) — the brief's 10-step debate route becomes a roadmap variant, not a new engine.
8. **Cost/reliability engineering the original lacks**: structured output with retries (`OpenAIResponsesClient`), deterministic heuristic fallbacks logged at $0, durable pg-boss queues instead of an in-memory job dict, DB CHECK-constrained taxonomies instead of free-text columns, budget seeding from `ai_usage_log` (crash-proof), and idempotent judgments keyed on sorted claim pair + basis hash (extending the existing `work_relationship_judgment.basisHash` discipline).

### Pipeline

Four independent queues (grouped by cost profile/trigger, payloads always `{requestId}`): `extract-research-claims`, `analyze-claim-debates` (relationship detection → clustering as one staged, resumable request — no lost-enqueue failure mode), `synthesize-research-output` (chamber + hypotheses, explicit action only), `import-research-corpus` (zero AI cost; monitors via `boss.schedule`, cadence defaults `paused`, flag default off). Registered with the `QUEUE_EXPAND_CROSS_LIBRARY_GRAPH` handler shape. **Claim extraction never auto-fires on upload** — it triggers on project membership (central/supporting), explicit action, or corpus import; nothing spends money without a user action.

- **Map-reduce extraction** (fixes the 32k truncation): `CLAIM_ELIGIBLE_BLOCK_KINDS = ['body']` allowlist (apparatus exclusion by block kind — a future new kind is excluded by default); GROBID-section-aware chunks ≤12k chars via the existing `chunkSectionAwareBlocks`; section-importance order until soft cap with `coverage='partial'` + the exact section list (never silent truncation); deterministic reduce (dedup + score + top-N — no reduce LLM call). **Excerpt fidelity zero-tolerance**: literal-substring check in `validate()` (retry), again before insert (drop, never repair), asserted in the canary. **No heuristic fallback for extraction** — an invented claim is worse than no claim; zero claims is the honest degraded state (documented deviation, same reasoning as `synthesizePassageAnnotations`).
- **Reprocess supersession**: `research_claim.processing_run_id` is `SET NULL`, claim identity is content-addressed; on republish a **free deterministic rebind** re-locates each claim via the shared `findQuoteOffset` (exactly-one match → `rebound`; else `unanchored`, visibly marked, never silently deleted — the user may have verified/cited it). `basis_hash` excludes block ids, so a pure rebind never re-pays for judgments.
- **Three-channel Stage 1**: dense cosine over pgvector (`<=>` cosine, HNSW-indexed; the pairwise scan may still run in worker memory at small N — both read the same typed vector column) ∪ BM25 ∪ **locus** (same `claim_locus.locus_key` → candidate at score 1.0; same work+section → 0.7; deterministic, free — ships even if dense calibration fails, and is the structural hedge against domain-transfer failure).
- **Citation-graph engagement**: deterministic pre-join (reusing `buildGraph()`'s citation→record→owned-work resolution, extracted to a shared helper): `direct_citation | reciprocal_citation | shared_citation | none_detected`, passed to the judge as context and stored. Treated as a measured hypothesis: the judge-eval spike includes an **ablation** (with/without engagement context); if it doesn't lift F1 it leaves the prompt but keeps the column (product-visible value regardless).
- **Budget**: `RESEARCH_COST_SOFT_CAP`/`HARD_CAP` reused per request; caps in `limits.ts` (`maxJudgedPairsPerRequest 40`, `maxCandidatePairs 400`, `maxClaimsInScope 3000`, etc.); pair detection is **project-scoped, never library-scoped** (bounds the O(n²) surface).

### Eval harness (two gold sets, two gates)

Gold sets live beside the prompts they gate (`packages/claims/src/eval/gold/` + PROVENANCE.md): the ported empirical 42 pairs; a **new humanities set (30–40 pairs)** labeled from the corpus already in-repo (`baseline-test/` Roochnik, `docs/eval/irwin-vice-and-reason/`, the eval-fixtures bucket); ≥20 deliberate humanities retrieval negatives (the separation harness's own honesty guard demands them); a `claimNature.json` (~64 claims). CI runs the free harness on every push (validators, schemas, metrics, drop-to-null paths); `RUN_PAID_EVAL=1` runs the real judge through the production code path with `persist:false`.

Gates (constants carrying their measurements): empirical judge `macro-F1 ≥ 0.75`, `kappa ≥ 0.60`, `contradiction recall ≥ 0.66`. Humanities branch promotes only if: base-4-way-on-humanities baseline measured first; branch beats it by ≥0.05; mechanism accuracy ≥0.60; empirical regression ≤0.02; no value below F1 0.40 — only then does the enum-widening migration run and the flag flip. **Until then humanities pairs run through the base judge, and the three mechanism values don't exist in the Postgres type — misclassification into them is impossible to persist.** A CI test fails the build if any enum value has <6 gold examples (staged taxonomy kept honest by construction). Judge model routing: run the paid eval nano → mini → haiku, promote the cheapest that clears (~$0.16 for all three), never on a spot check. **No gate may be declared passed on a pooled number alone — per-domain breakdown mandatory** (domain-transfer failure is risk #2).

Graph: `NodeType` gains `claim`/`debate` (additive), synthetic edge strings with `EDGE_TYPE_FAMILY` entries; **progressive disclosure is load-bearing** — `buildGraph()` emits at most one debate node per cluster at default zoom (≤40), claims arrive only via explicit expand (≤60/expansion) through an additive delta endpoint; the accessible table covers debate nodes and expansions (non-optional). Writer: Evidence panel inserting blockquote nodes with `researchClaimId` attrs + `writer_citation` rows built only from real bibliographic records. Ask Library: per-message `mode` (`find_counterarguments` retrieves via the relationship graph, not lexical chunks; `explain_disagreement` must cite ≥1 claim per side or return not-found; `map_debate`; `find_support`), claim citations allowlist-validated like chunk citations, cost sharing the existing daily pool.

## Execution methodology: dynamic workflows, parallel agents, lower-model subagents

The program executes the way the Phases 19–24 completion program and the v.5 UX program did — orchestrated multi-agent lanes with cost-efficient model assignment — with these standing rules:

- **Model assignment per task class** (recorded in `docs/project-status.json`'s `program` block):
  - **Haiku 4.5** — mechanical work: doc syncs, tracker regeneration, gold-set JSON transcription, label audits, link checks, test-fixture transcription, changelog upkeep.
  - **Sonnet 5** — default implementation tier: pipeline stages, UI surfaces, API routes, tests, eval-harness port, prompt transcription.
  - **Opus / high tier** — high-stakes, hard-to-reverse work only: schema migrations + CHECK constraints, the shared evidence-model data contract, taxonomy design, judge-prompt adaptation + eval sign-off, correction/versioning model, production rollout gates.
- **Dynamic workflows** (the Workflow tool) for fan-out phases: parallel finder/implementer lanes per sub-phase, pipeline() (no barriers) for independent lanes, adversarial verification of every lane's output before merge (the pattern that caught 12+ real pre-merge defects in the live-issue program). Verification agents get distinct lenses (grounding correctness, cost-cap compliance, taxonomy honesty, a11y) rather than N identical reviewers.
- **Worktree isolation** for parallel implementation lanes (the `/private/tmp/palimnote-lane-*` pattern), merged serially through the typecheck/lint/test/build gate; schema and shared-contract work always serializes on `main` ahead of dependent lanes (D-23-34 rule: migrations applied to production before or with the code push that reads them).
- **Eval-gated promotion**: no prompt or model-tier change ships without a gold-set eval run; cheapest tier first, promoted only on measured evidence (macro-F1/kappa floors set per stage).
- **Paid canaries** only at phase gates, within the standing $1/$5 caps, cleaned up and cost-logged (existing authorization covers this).
- **Tracker discipline**: `docs/project-status.json` gains the new phases with per-sub-phase model assignments; `pnpm generate:project-status` + `check:project-status` after every closeout; `docs/PROJECT-LOG.md` updated per the Tracker Workflow.

## Verification

- Per-lane: `pnpm -r typecheck && pnpm -r lint && pnpm -r test`, `pnpm --filter web build`, plus the lane's own Playwright spec(s) run against a built server.
- Per-phase gates: eval-harness runs (macro-F1/kappa vs floors), serialized full-stack E2E for pipeline phases, axe wcag2a/wcag2aa zero-violation on every new surface, and a paid canary where a phase changes worker AI behavior.
- Program close: Phase 24 executes over the merged product — full local matrix, full serialized E2E suite, production smoke + final canary, program closeout.
