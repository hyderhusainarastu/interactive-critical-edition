Production Research Workspace

Active

Seven parts turn Palimnote into a production research and writing workspace. Each is committed, verified, logged, and pushed before the next begins. Parts 1–4 establish the shell, canonical source identity, filtering rules, release-gated v4 data pipeline, and an interactive processed-text reader that later work consumes.

  1. 12.1 · Foundation and site-wide UX

    Responsive shell, compact headers, mobile drawer, command palette, toasts, recovery states, feature flags, preferences, and desktop/mobile baselines. Complete.

  2. 12.2 · Library, identity & source coverage

    Canonical source aggregation, verified SHA-256 duplicate resolution, transparent source labels, curated Blogger coverage, public Reddit web-search metadata only, and cumulative/exact level filtering. Complete locally; release flag remains off pending production migration approval.

  3. 12.3 · Pipeline v4 & annotations

    Eight capped section-aware chunks, grounded deduplicated annotations with helpful purpose/scope, independent source apparatus, compact embeddings/candidates, and an admin-only dry-run forecast. Complete locally; v4 flag and production backfill remain off pending approval.

  4. 12.4 · Interactive reader

    Release-gated processed text with original-file labels, outline/position/annotation navigation, focus mode, many-to-many note links, author apparatus filters, and verified script terms. Complete locally; production migration and flag remain off.

  5. 12.5 · Cross-library graph

    Cached claim relationships, evidence workspace, accessible graph data, and budgeted expansion.

  6. 12.6 · Writer mode

    Private projects, structured MLA drafting, source sidebar, citations, and export.

  7. 12.7 · Production hardening

    Authenticated APIs, telemetry, audits, visual coverage, and safe destructive actions.

Phase 10 — Workspace Depth & Adaptivity Completion (complete)

All six audited scope items shipped, tested, and production-canary-verified where AI-pipeline-touching. Kept here for reference.

  1. Annotation relationship & source link

    Surface each passage annotation's relationship category and a link to its related resource. Pure UI, no new schema or AI call. Complete.

  2. Annotation filter & sort

    Filter/sort annotations by category and review status, plus a sort control, mirroring the Library's established pattern. Complete.

  3. Library default-scoping

    Reader-level scoping becomes the default view (with an explicit "show all"), matching Roadmap and Curriculum's established pattern. Complete.

  4. 3D graph visual richness

    Directional link particles, neighbor-subgraph hover highlight, click-to-focus camera fly-to — still driven by the same palette tokens. The accessible table stays an equal, unchanged fallback. Complete.

  5. Suggested reader level

    A level nudge derived from aggregate Library completion patterns — a suggestion the reader can accept or ignore, never a silent overwrite. Complete as a pure read-time feature; no canary needed.

  6. Jargon-extraction tightening

    Verify and, if needed, tighten the passage-annotation extraction prompt so it reliably targets terminology/jargon, not just general commentary. Complete; production-canary-verified (4 of 7 seeded annotations correctly typed "definition" against real Greek/Latin technical vocabulary).
